A. Why normal binary search is not enough

Binary search relies on one fact: the order tells you which side the target is on. Pick a scenario.

B. Which half is sorted?

Test: nums[left] <= nums[mid]. Try the scenarios and watch the green half.

Why is checking only one condition enough?

At least one half of any range is always sorted, because the array has only one drop (the rotation point) and it can sit in just one half. So we ask one question. If the answer is “left is sorted” we use it. Otherwise the drop is on the left, so the right half is guaranteed sorted. If there is no drop at all, both halves are sorted and picking the left one is still correct.

C. Does the target belong to the sorted half?

A sorted half is a trustworthy ruler: if the target is between its two ends, it must be inside. If not, it must be in the other half.

D. Moving the pointers

After the decision, one whole half plus the mid is thrown away. Faded boxes are eliminated.

Why mid ± 1 and not just mid?

mid was already compared with the target and failed, so it can never be the answer. Moving to mid + 1 or mid - 1 removes it and guarantees the range always shrinks (no infinite loop).

Key ideas

Multi-source BFS: every zero is pushed before the loop and given distance 0. All zeros are distance-0 sources, so BFS expands from all of them at once; starting from only the first zero would give wrong answers for cells nearer to another zero.

Why shortest: BFS processes cells in order of distance (all 0s, then all 1s, then 2s…). The first time a cell is reached is via the shortest path in an unweighted grid.

d vs mat vs Q: mat = original 0/1 input; d = computed distances (and the visited record); Q = cells waiting to be explored. The update uses d[rs][cs]+1, not mat, because mat is only 0 or 1.

Visited check d[nr][nc] == -1: a cell is unvisited only while it holds -1. Once assigned, other paths fail the check, so it’s never overwritten or enqueued twice. Checking mat[nr][nc] == -1 would be wrong: mat never contains -1, so the test would never be true.

Code notes: int distance = 0; is unused and can be removed. Naming the column-direction vector j clashes visually with loop variables; c would be clearer. Neither is a logic error.

Algorithm summary

Initialize d with -1
        ↓
Enqueue every zero and set its distance to 0
        ↓
Is queue empty?
  No ↓         Yes → Return d
Read front cell
        ↓
Check four neighbors
        ↓
Valid and unvisited?
   Yes → Assign current distance + 1 and enqueue
   No  → Skip neighbor
        ↓
Repeat

Time: O(n × m) · Auxiliary space: O(n × m). Each cell is enqueued at most once (the -1 check guarantees it), and each dequeued cell does 4 constant-time neighbor checks.

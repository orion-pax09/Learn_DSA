Complexity on this graph

   
O(V+E) time: each vertex is pushed/popped once (a vertex is pushed only while vis==-1), each adjacency entry is scanned once (2E entries). O(V) space: vis has V ints; the queue never holds more than V nodes.

 





Why the outer for loop exists


Outer for = visits every vertex and starts a BFS at each one that is still -1 → covers every connected component.
Inner while = BFS inside one component.


Open C: Disconnected and press Next: BFS starts at 0 (colors 0,1), the loop skips 1, starts at 2 (colors 2,3), skips 3, then starts at 4 (isolated). If you only ran BFS from node 0, vertices 2, 3, 4 would stay uncolored, and a hidden odd cycle there (e.g. a triangle on 2-3-4) would be missed — the function would wrongly return true.


Deep concepts


What is a bipartite graph?Vertices can be split into two groups so that every edge joins different groups. Colors 0 and 1 are the two groups; a valid coloring is a proof.


Why does an odd cycle cause a conflict?Colors must alternate around a cycle. After an odd number of steps you return to the start with the other color, so one edge always joins equal colors. Watch it:  


Why are even cycles fine?Alternating colors around an even cycle lands back on the starting color. Compare  with the triangle.


Why BFS?BFS handles a node’s neighbors together, then their neighbors: level by level. Levels naturally alternate colors (level 0 = 1, level 1 = 0, …), which is exactly what 1 - vis[x] produces.


Why color on discovery, not on pop?If we waited for pop, a node still has -1 while waiting in the queue, so another neighbor could push it again (triangle: node 2 would be pushed by both 0 and 1). Coloring when pushed marks it “seen” immediately, so each vertex enters the queue once.
